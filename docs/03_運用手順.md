# 運用手順

> 実データ（氏名・単価表・カード対応表・資料）はリポジトリに入れず、本番環境で登録する。

## 1. 本番環境の作成（Render）
1. Render にログインし、「New → Blueprint」でこのリポジトリを選ぶ（`render.yaml` を読み込む）
   - 作成されるのは、Web サービス `kanri` と PostgreSQL `kanri-db` の2つ
   - どちらもシンガポールリージョン
2. 作成時にプラン名と料金を確認する
   - データベースは、毎日自動でバックアップされる有料プランにする
3. Web サービスの Environment に次の値を設定する
   - `ALLOWED_HOSTS`：例 `kanri.onrender.com`（独自ドメインを使うならそれも、カンマ区切り）
   - `CSRF_TRUSTED_ORIGINS`：例 `https://kanri.onrender.com`
   - `COMPANY_NAME`：会社名
   - `ISSUER_REPRESENTATIVE`：例 `代表取締役 〇〇 〇〇`
   - `ISSUER_ADDRESS`、`ISSUER_TEL`：明細書の発行者欄
4. デプロイすると、`preDeployCommand` でデータベースの初期化（migrate）が自動で行われる

## 2. 初期設定（Render の Shell で1回だけ実行）
```bash
python manage.py createsuperuser                      # 代表者のログインユーザー（あとで権限を「代表者」に）
python manage.py set_stepup_password --scope payroll  # 給与用の追加パスワード（対話入力・ハッシュ化して保存）
python manage.py set_stepup_password --scope expenses # 経費用の追加パスワード
python manage.py import_legacy_payroll_setup 給与計算.xlsx --effective-from 2026-01           # 確認
python manage.py import_legacy_payroll_setup 給与計算.xlsx --effective-from 2026-01 --apply   # メンバー・単価表を登録
```
- ファイルは Shell にアップロードして使い、終わったら削除する
- 追加パスワードはあとから画面（右上「追加パスワード」・代表者のみ）で変更できる

画面（管理画面）で登録するもの:

| 登録するもの | 場所 | 内容 |
|---|---|---|
| メンバーの補足 | メンバー → 編集 | 正社員の登録、入社日、代理店、インターンの登録、シフト表で姓だけの人の「別表記」 |
| カード対応表 | メンバー → カード対応表 | マニュアルの4桁と担当者。正社員のカードは「給与に反映しない」。表にないカードは自動で無視される |
| チーム | 給与 → 設定 → チーム | 営業チーム（チーム達成ボーナス）と、インターンチーム（リーダー手当） |
| 商材別報酬の人 | 給与 → 設定 → 給与項目 | 商材別の項目（プロパン・都市ガス・電気）の「対象者」に追加し、「営業報酬」の「対象外にする人」に追加する |
| 個人専用の項目 | 給与 → 設定 → 給与項目 | 例：サウナコンサル。計算方法「金額を毎月入力」、適用範囲「個人専用」 |
| 正社員の基本給 | 給与 → 正社員 | 基本給と、その適用開始月 |

既存シフト表を取り込むとき:
```bash
python manage.py import_legacy_shift シフト表.xlsx          # 確認（姓だけの名前は別表記の登録が必要）
python manage.py import_legacy_shift シフト表.xlsx --apply
```

## 3. 毎月の流れ
1. **シフト**：シフト表で入力し、「画像を作成」でLINEに貼り付ける
2. **勤怠**：実績を確認・修正し、月末に「この月の勤怠を確定」を押す
3. **資料・経費**（追加パスワードが必要）
   - ENEOS の請求書PDF をアップロードする
     - カードの4桁を自動で読み取り、9月分なら10月の給与に反映する設定になる
     - 「金額の確認」欄で、ページ画像を見ながらカード別の金額を入力・確定する
   - 交通費の請求書PDF をアップロードする（8月分なら10月の給与に反映）
   - LINE で届いた経費は「LINEなどで届いた経費を入力」に「氏名 金額」の形で貼り付ける
   - 確認待ちを解決してから、すべて承認する
4. **営業件数**（給与・報酬 → 営業件数の入力）
   - 前月の獲得件数（ダッシュボード）と、当月の入金確定件数（入金確定シート）を入力する
   - 文面や表のコピーを貼り付けると、件数を読み取ってくれる
5. **計算**：「給与データを作成」→「全員を計算」を押し、「入力途中」の人は足りない値を入力する
6. **確認・確定**：一人ずつ内容を確認して確定する。当月だけの項目（プロパンガスなど）は、確定する前に追加する
7. **明細**：「明細PDF（確定分を一括）」で全員分を出力する

## 4. バックアップと復元
- データベースは Render が毎日自動でバックアップする（有料プラン）
  - アップロードした資料・写真もデータベースに保存しているので、一緒にバックアップされる
- 復元：Render のデータベース画面の「Recovery / Backups」から、指定した時点に戻す
  - 戻す前に、必ず現在の状態のバックアップを取っておく
- 手動で控えを取る（Shell）：
  ```bash
  python manage.py dumpdata --exclude contenttypes --exclude auth.permission --exclude sessions -o backup.json
  ```
  - `backup.json` には個人情報が含まれるので、保管場所に注意する

## 5. 安全のための注意
- 給与と経費は、それぞれ別の追加パスワードがないと、画面・PDF・CSV・管理画面・資料ファイルのどれも開けない
  - 30分操作がないとき、またはログアウトすると、再入力が必要になる
- 5回続けて間違えると15分ロックされる
  - 入力の成功・失敗・ロックは操作履歴に残る
- 確定した給与と操作履歴は、データベース側でも変更・削除できない
  - 確定を取り消すときは理由の入力が必要で、確定時の内容は履歴に残る
- このリポジトリは公開設定。非公開にすることを推奨する
