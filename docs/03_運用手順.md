# 運用手順

> 実データ（氏名・単価表・カード対応表・資料）はリポジトリに入れず、本番環境で登録する。

## 1. 本番環境の作成（無料構成：Render ＋ Neon）
無料構成の注意点:
- しばらく使わないとサーバーが停止し、次に開くとき1分ほど待つ
- データベースは1GBまで
- 自動バックアップがないため、**月に1回、画面からバックアップをダウンロード**する
- 画像PDFの読み取り（OCR）に時間がかかる。失敗した場合は金額を手入力する

### 1-1. データベース（Neon）
1. https://neon.com でアカウントを作る（無料）
2. 「New Project」を作る
   - Region はアジア（例：Singapore）、Postgres のバージョンは 16 以上
3. 「Connection string」（`postgresql://...?sslmode=require`）をコピーする
   - これは**パスワードを含む秘密の値**なので、他人に共有しない

### 1-2. Webサーバー（Render）
1. https://render.com でアカウントを作り、GitHub と連携する
2. 「New → Blueprint」でこのリポジトリを選ぶ（`render.yaml` を読み込み、無料プランの Web サービス `kanri` を作る）
3. Environment に次の値を設定する

| 名前 | 設定する値 |
|---|---|
| `DATABASE_URL` | Neon の接続文字列 |
| `ALLOWED_HOSTS` | Render が付けたアドレス（例：`kanri-xxxx.onrender.com`） |
| `CSRF_TRUSTED_ORIGINS` | `https://` を付けたアドレス |
| `COMPANY_NAME`、`ISSUER_REPRESENTATIVE`、`ISSUER_ADDRESS`、`ISSUER_TEL` | 明細書・シフト画像に出す会社情報 |
| `INITIAL_ADMIN_USERNAME`、`INITIAL_ADMIN_PASSWORD` | 最初の代表者ユーザー |
| `INITIAL_PAYROLL_PASSWORD`、`INITIAL_EXPENSES_PASSWORD` | 給与用・経費用の追加パスワード |

4. デプロイすると、起動時に次の処理が自動で行われる
   - データベースの初期化
   - 代表者ユーザーと追加パスワードの作成（未設定の場合のみ）
5. ログインできたら、`INITIAL_` で始まる4つは削除してよい
   - 設定済みの値は上書きされないので、残しておいても害はない
   - 追加パスワードは画面から変更できる

## 2. 初期設定（画面から）
1. 代表者でログインし、右上の「設定・バックアップ」を開く
2. 給与・報酬を開いて追加パスワードを入力してから、「既存の給与計算ブックから取り込む」を実行する
   - まず確認だけ行い、問題なければ「取り込む」にチェックして再実行する
   - メンバーと単価表が登録される
3. 管理画面で次のものを登録する

| 登録するもの | 場所 | 内容 |
|---|---|---|
| メンバーの補足 | メンバー → 編集 | 正社員の登録、入社日、代理店、インターンの登録、シフト表で姓だけの人の「別表記」 |
| カード対応表 | メンバー → カード対応表 | マニュアルの4桁と担当者。正社員のカードは「給与に反映しない」。表にないカードは自動で無視される |
| チーム | 給与 → 設定 → チーム | 営業チーム（チーム達成ボーナス）と、インターンチーム（リーダー手当） |
| 商材別報酬の人 | 給与 → 設定 → 給与項目 | 商材別の項目（プロパン・都市ガス・電気）の「対象者」に追加し、「営業報酬」の「対象外にする人」に追加する |
| 個人専用の項目 | 給与 → 設定 → 給与項目 | 例：サウナコンサル。計算方法「金額を毎月入力」、適用範囲「個人専用」 |
| 正社員の基本給 | 給与 → 正社員 | 基本給と、その適用開始月 |

4. 「既存のシフト表から取り込む」で、過去のシフトを取り込む（任意）

コマンドが使える環境（開発用のPCなど）では、同じことを `import_legacy_payroll_setup`・`import_legacy_shift`・`set_stepup_password` で行える。

## 3. 毎月の流れ
1. **シフト**：シフト表で入力し、「画像を作成」でLINEに貼り付ける
2. **勤怠**：実績を確認・修正し、月末に「この月の勤怠を確定」を押す
3. **資料・経費**（追加パスワードが必要）
   - ENEOS の請求書PDF をアップロードする
     - カードの4桁を自動で読み取り、9月分なら10月の給与に反映する設定になる
     - 「金額の確認」欄で、ページ画像を見ながらカード別の金額を入力・確定する
   - 交通費の請求書PDF をアップロードする（8月分なら10月の給与に反映）
   - LINE で届いた経費は「LINEなどで届いた経費を入力」に「氏名 金額」の形で貼り付ける
   - 確認待ちを解決してから、すべて承認する
4. **営業件数**（給与・報酬 → 営業件数の入力）
   - 前月の獲得件数（ダッシュボード）と、当月の入金確定件数（入金確定シート）を入力する
   - 文面や表のコピーを貼り付けると、件数を読み取ってくれる
5. **計算**：「給与データを作成」→「全員を計算」を押し、「入力途中」の人は足りない値を入力する
6. **確認・確定**：一人ずつ内容を確認して確定する。当月だけの項目（プロパンガスなど）は、確定する前に追加する
7. **明細**：「明細PDF（確定分を一括）」で全員分を出力する

## 4. バックアップと復元
- **月に1回**、「設定・バックアップ」→「バックアップをダウンロード」で保存する
  - 給与と経費の両方の追加パスワードを入力してから実行する
  - シフト・勤怠・給与・経費・資料ファイル・操作履歴が1つのファイル（`kanri-backup-日時.json.gz`）に入る
  - **個人情報と給与情報が含まれるので**、パスワード付きの場所などに安全に保管する
- 復元するとき
  1. Neon で新しいプロジェクト（空のデータベース）を作り、Render の `DATABASE_URL` をそれに切り替えて再デプロイする
  2. ログインして「設定・バックアップ」を開く
     - データが空のときだけ「バックアップから復元」が表示されるので、ファイルを選んで実行する
     - 途中で失敗した場合は何も変更されない
  3. 復元が終わったら、バックアップ時のユーザーでログインし直す
  - コマンドが使える環境では `python manage.py restore_backup <ファイル>` でも復元できる
  - 復元中だけ確定済みデータの保護を一時的に外し、終わると元に戻る
- 有料プランに切り替えると、データベースが毎日自動でバックアップされる

## 5. 安全のための注意
- 給与と経費は、それぞれ別の追加パスワードがないと、画面・PDF・CSV・管理画面・資料ファイルのどれも開けない
  - 30分操作がないとき、またはログアウトすると、再入力が必要になる
- 5回続けて間違えると15分ロックされる
  - 入力の成功・失敗・ロックは操作履歴に残る
- 確定した給与と操作履歴は、データベース側でも変更・削除できない
  - 確定を取り消すときは理由の入力が必要で、確定時の内容は履歴に残る
- このリポジトリは公開設定。非公開にすることを推奨する
